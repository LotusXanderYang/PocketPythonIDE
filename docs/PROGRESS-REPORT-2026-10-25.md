## 当前质量和交付风险

1. **Git 工作区尚无本地提交。** `git status --short --branch` 显示 `No commits yet on main`；大量阶段源码、文档与模块处于已暂存、未暂存或未跟踪状态。远端 beta.5 Release 是外部回退锚点，但当前阶段 1–5 代码还没有本地提交级回退点。不能执行 `reset --hard`、`clean` 或盲目全量暂存。整理源文件、检查忽略项并建立可审阅的本地快照，是继续扩大改动面前最有价值的保护措施。
2. **工作区复制上限不一致。** `WorkspaceFiles.copyToMirror()` 可复制总计 512 MiB、单文件 256 MiB；语言包输入 `PackClient.zipWorkspace()` 只接受总计 8 MiB、单文件 1 MiB。当前构建/检查可能先读取大量 SAF 文件，随后才因语言包输入上限失败。带数据或媒体文件的课程目录更容易碰到这一路径。应在复制前区分语言包所需源码/配置与一般运行数据，提前校验并给出具体文件名和限制；不能悄悄遗漏源码。
3. **设备覆盖面仍窄。** C/C++ 原生详细验证集中在 Android API 36、ARM64、4 KB 页设备；API 26、16 KB 页、真正全新 IDE 安装与最终 APK 的鸿蒙卓易通原生日志缺失。Lab 阶段 7 仍需独立复测新 APK，不能继承旧版 PyTorch 自检结论。
4. **文档存在历史状态。** 根 README 主要介绍 beta.5；`docs/architecture/dual-app-split.md` 仍以阶段 2 当时的模块数、APK 大小和 Lab 未验证状态叙述。它们应保留为历史记录，但首页需要清楚指向当前产品、最新调试包和阶段验收记录，避免新读者误把旧快照当现状。
5. **体积与维护成本可见。** C/C++ APK 的裁剪工具链 ZIP 为 71,827,933 字节，占 APK 大约 97.7%；MAG-AN00 上私有工具链约 244,172 KiB。`WorkbenchActivity.java` 约 2,600 行，界面、文件、任务、补全和设置仍集中；继续增加 Python 包与调试功能会提高回归风险。
6. **可复现与大目录响应尚需独立验证。** 工具链有版本锁定和脚本，但没有记录从全新克隆完成两包构建的端到端结果。`refreshFiles()` 在界面线程枚举 SAF 树，云盘或较大目录可能拖慢文件列表；这是代码路径推断，当前没有设备耗时测量。

## 建议的优化顺序

| 优先级 | 建议 | 为什么现在做／验收标准 |
| --- | --- | --- |
| 高：继续开发前 | 对当前阶段 1–5 文件做只读清单、区分生成物和源码，保留现有暂存/未暂存内容，再建立可审阅的本地 Git 快照 | 先获得可回退的代码状态；不触碰 beta.5 标签或用户设备数据。该动作需单独执行，不应在本报告里盲目提交 |
| 高：阶段 6 设计时 | 为语言包准备按项目配置选择的输入快照，并在 SAF 复制前做上限预检；对超限文件报清楚路径 | 避免 512 MiB 复制后才触发 8 MiB 拒绝；回归多文件 C/C++、大文件失败、取消与原工作区不变 |
| 高：公开发布前 | 补齐旧版私有脚本显式导出和可验证迁移，完成 API 26/16 KB 页与空安装端到端测试；核对每个发布 APK 的许可证、签名、哈希和源码提交 | 当前有迁移设计和部分设备证据，但不能用其代替发布验收 |
| 中：近期文档整理 | 在根 README 增加“当前开发状态”，分别指向 IDE、Lab、API、C/C++ 包和最新验收；给历史阶段文档标注快照日期 | 不改历史结论，同时让新用户知道最新支持边界 |
| 中：有明确体积目标时 | 在隔离试验中评估仅 AArch64 后端的 LLVM 或 C/C++ 拆包，记录下载、解包和编译耗时；以现有课程样例回归 | 70.15 MiB 包体积是最大下载成本。不能先删除当前可运行工具链，也不能隐藏下载 |
| 中：阶段 6–8 迭代中 | 按任务控制、SAF 工作区、编辑器和设置逐步拆出 `WorkbenchActivity`，每次只改一条可测路径 | 降低 2,600 行活动类的改动风险；避免一次性重写破坏已通过的平板交互 |
| 中：有大目录样例时 | 测量 `refreshFiles()` 的 SAF 查询耗时，再决定是否缓存、分页或转到后台；另从干净克隆跑一次锁定工具链构建 | 先取得具体耗时与失败点，再做性能和复现改造，避免无根据地大改 |
| 低：第三方生态前 | 补齐预构建 SDK AAR 或稳定的源码依赖示例，继续保持 Schema/验证器与文档一致 | 当前 SDK 源码可用，但第三方接入成本偏高；不阻挡下一阶段的内置语言包 |

下一阶段如由用户启动，阶段 6 的重点是**独立的基础 Python 语言包**；通用 IDE 基础 APK 应继续不包含 Python/PyTorch 运行时。阶段 7 才对 Lab 的训练、检查点与资源指标做正式验收。阶段 8、9 仍待后续明确执行与发布授权。
