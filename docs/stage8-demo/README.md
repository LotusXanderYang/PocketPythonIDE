# 阶段 8 实机演示

设备：ARM64 Android MAG-AN00，ADB 可用。直接覆盖安装本阶段 `ide-debug.apk` 与 `python-debug.apk`，不要清除数据。在 IDE 的“语言包”选择 `com.example.pocketpythonstd`，执行“验证并启用”和“启用通过的能力”；其中 `debug` 应通过。

将 `stage8_main.py` 和 `stage8_helper.py` 放在同一可写工作区。打开 `stage8_main.py`，直接点编辑器第 3 行行号，确认出现断点圆点；再点顶部“调试”。调试态左侧显示变量、调用堆栈和断点，编辑区上方显示继续、暂停、单步、步入、步出、停止控制，底部“调试控制台”显示输出。预期暂停在 `stage8_main.py:3`，当前执行行出现箭头与行高亮；“单步”到第 4 行，输出 `stage8-result: 42`；“继续”在第 5 行 `ValueError` 停住，再“继续”显示退出码 1。也可先在常规编辑器打开 `stage8_helper.py`，对第 2 行加断点，再回到主文件启动；调用栈应同时有 helper 和 main，局部变量 `number=21`。点调用栈行应在常规编辑器中跳转到对应源文件。调试停止后，左侧恢复原文件树，底部调试控制台保留本次输出供核对。

断点迁移样例：结束调试后，用 `stage8_renamed.py` 替换原文件（它在顶部插入一行并改名），再从常规编辑器启动调试。原第 3 行断点应迁移到新文件第 4 行，启动后停在 `stage8_renamed.py:4`。同一逻辑适用于 SAF 工作区再次复制后的行位移；歧义映射会提示用户检查。

重复会话回归：保留同一组断点，不改文件，连续启动两轮调试。两轮都应命中同一断点，底部首先显示“已提交 N 个断点”；暂停时点“暂停”应提示当前已暂停，随后“单步”或“继续”应照常执行。停在断点超过两分钟也不应自动超时退出。若发生异常，请记录底部 `[调试]` 行、左侧断点行号与状态文字。

C++ 的 `stage8_ptrace_main.cpp`、`stage8_ptrace_helper.cpp` 和 `.pocket-cpp.json` 要放在同一个独立工作区。启用 `org.idecpp` 后运行 main，预期 `stage8-ptrace:0`。这只验证同应用子进程的基础 `PTRACE_TRACEME`/`PTRACE_CONT`；它不是 LLDB 调试演示，C++ 包仍不提供 IDE 断点调试。
