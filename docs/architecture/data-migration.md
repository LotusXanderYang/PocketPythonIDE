# 旧应用到双应用的数据迁移设计（阶段 1）

本文件定义后续实现与验收合同；阶段 1 **没有新增迁移 UI，也没有移动用户数据**。旧版 `com.example.pocketpythonide` 与未来通用 IDE、Python · PyTorch Lab 使用不同 `applicationId` 并存。两个新包名留待阶段 2 确定，绝不能用旧包名升级覆盖 beta.5。

## 数据归属与边界

| 数据 | 当前归属 / 位置 | 迁移方式 |
| --- | --- | --- |
| 旧应用私有脚本 | 旧包 `getFilesDir()/scripts`；当前代码只列出 `.py`，用户编辑内容仍归旧包 | 必须由旧应用在用户点击“导出”后通过 SAF 创建归档；新应用不能读取旧包私有目录，也不能依赖卸载/Android 备份 |
| SAF 外部工作区 | 用户选择的文档提供者；旧包仅持有持久 URI 授权和 `workspace_tree_uri` 偏好项 | 文件仍在原提供者。用户在每个新应用中重新选择同一目录、重新授权；不要复制旧 `content://` 字符串或假定原生鸿蒙目录可写 |
| 工作区运行副本 | 旧包 `getFilesDir()/workspace-runs`，冲突/写回失败时可能保留 | 不自动当作工作区真源；导出界面须单列可恢复副本供用户预览与选择，并标注其来源和与外部文件的差异 |
| 编辑器设置 | 旧 Activity 私有偏好，如 `editor_font_size_sp`（10–32 sp）；工作区 URI 也是偏好，但不是可转移授权 | 只导出白名单中有意义的设置；字体值先验证范围。新应用分别导入自己的设置，不导入授权 token |
| 运行时、缓存、日志 | 旧包及 `.toolchain/` 构建缓存；`runtime.zip` 是构建资产 | 不作为用户脚本迁移；Lab 使用经核验的自身运行时，通用 IDE 不继承大型运行时 |

`android:allowBackup="false"`，因此不能把系统自动备份当作跨包迁移方案。旧版应用当前没有完整的私有脚本导出流程；这项能力是后续实现门槛。在它完成前，**不得**指导用户删除旧包来迁移。

实现旧包导出入口时，可制作独立的后续维护版本，在签名一致且用户同意升级的前提下原位安装，保留旧包私有数据；不得修改已发布的 beta.5 标签或附件。该维护版本与两个新包并存。若签名不同而无法原位升级，普通新应用无法读取 beta.5 私有脚本，此迁移路径应标为受阻并保留原安装与数据，不通过卸载解决。当前既未制作维护版本，也未验证签名升级路径。

## 用户操作与实现流程

1. 用户先在 beta.5 保存打开的编辑内容。旧应用提供显式“导出我的数据”，列出私有脚本、可恢复的运行副本、字体设置及所选 SAF 工作区的名称；用户勾选要导出的项目。外部工作区默认仅记录提示与相对文件清单，不因导出而修改原目录；如用户要求离线副本，再经现有授权只读复制。
2. 旧应用通过 `ACTION_CREATE_DOCUMENT` 让用户选择归档位置，生成 ZIP 与 `manifest.json`：格式版本、旧应用 ID/版本、导出时间、每个相对路径的大小及 SHA-256、数据类别和设置白名单。写到临时目标并验证完整性后再显示“导出成功”；若 SAF 提供者不支持可靠替换，使用新文件名，失败时标明不完整文件且保留旧数据。不得隐式上传。
3. 用户可在文件管理器或导出页核验归档大小与 SHA-256，并保留原归档。新 IDE 或 Lab 各自通过 `ACTION_OPEN_DOCUMENT` 选择该归档；导入前展示来源、清单、目标应用、项目数、总大小、异常项及冲突预览。两应用分别由用户操作，互不读取对方私有目录。
4. 对外部 SAF 工作区，优先由用户在新 IDE 里重新打开同一目录。先只读列目录并试探提供者能力；写入须另经真实保存测试。若目录是 MRO-W00 的原生 `我的平板/个人/PythonProject`，应明确提示已知拒写记录并建议用户选择兼容环境中可写目录，不能声称所有鸿蒙目录可写。Lab 如需要数据集目录，也由用户单独授予，默认只读。
5. 对私有脚本，在新应用私有目标或用户选定的新工作区中按相对路径导入。导入前逐项检查重名、大小、哈希、目标是否可写。重名时提供“跳过”“改名导入”“逐项比较后替换”选择；默认跳过。替换必须再次确认，并先保存旧目标的可恢复备份。不能用批量静默覆盖。
6. 导入后重新读取目标并逐项核对 SHA-256，展示成功、跳过、改名、失败及备份位置。只在完整核验后标记“迁移完成”。用户手动确认新应用可打开和运行项目之前，旧应用和导出归档都保留。

## 失败、安全与回退

- 解析归档时拒绝绝对路径、`..`、重复路径、符号链接及超出配额的文件；按流处理并核对每个文件哈希，避免部分解包或 ZIP 炸弹。不得将脚本、数据集或私有路径发往网络。
- `content://` 是文档 URI，不是本地路径；导入/导出须使用 ContentResolver 流。提供者拒写、空间不足、授权撤销、设备中断时保留旧包和原文件，显示已完成/未完成清单及可重试入口。写回时沿用当前工作区的读取哈希与冲突检测思想；外部文件变化时停止替换并让用户选择。
- 目标同名替换、运行生成文件和检查点均遵循同一显式选择规则。Lab 的训练输出采用新名称或版本化目录，不能覆盖已有检查点。
- 回退时仍可直接启动旧 beta.5；新应用导入的副本独立处理。按导入记录恢复被替换目标或删除用户确认的新副本，不触碰旧包数据。若旧包签名与待装 APK 不同，先完成导出核验，不能通过卸载旧包来解决。

后续阶段的迁移验收至少覆盖：私有 `.py` 与设置、SAF 同目录重新授权、运行副本选择、同名文件的三种选择、提供者拒写、哈希不符、中断重试，以及迁移后旧包仍可启动且脚本未变。当前仅完成设计，以上路径全部待实现和实机验证。
