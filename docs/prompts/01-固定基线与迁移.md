# 阶段 1 提示词：固定 beta.5 基线与用户数据迁移

请执行本阶段，并遵守 `docs/prompts/00-共同约束.md`。此阶段只处理基线、现状清点、回归和迁移设计；不要开始 UI 重做或语言包移植。

## 任务

1. 只读检查 Git 当前分支、HEAD、暂存区、工作区、未跟踪文件和现有 APK／运行时产物。核对 `v0.1.2-beta.5` GitHub Release 与本地 `versionName` 的关系；如网络不可用，记录未核对，不猜测。
2. 为现有编辑器、SAF 工作区、文件创建、保存、跨文件 Python 导入、运行、补全、键盘缩进和字体调节整理一份可重复的回归清单。分清已在 MAG-AN00、MRO-W00 和宿主机验证的项目；不要把旧版测试当作新版测试。
3. 设计旧版数据迁移：旧应用与两个新应用并存；用户可把工作区文件、运行脚本和必要设置导出、核验并导入。对于 SAF 选择的外部文件夹，优先复用用户重新授权的目录；对于旧应用私有脚本，必须提供显式导出流程。导入遇到同名文件时让用户选择，而不是覆盖。
4. 写明源码和二进制运行时的来源、哈希、许可证以及复现入口。保留现有缓存和断点构建资料，不重新编译 PyTorch。
5. 给出后续各阶段使用的基线检查命令、最小构建命令和设备验证命令，并确保命令不会清空工作区。

## 交付物

- `docs/architecture/beta5-baseline.md`：版本、产物、哈希、当前未提交状态和可回退步骤。
- `docs/architecture/regression-matrix.md`：功能 × 设备 × 测试状态矩阵。
- `docs/architecture/data-migration.md`：迁移流程、冲突处理、失败恢复与用户操作说明。
- 如需辅助脚本，只新增非破坏性的只读检查脚本，附运行结果；不要把现有文件批量暂存或提交。

## 验收

- 能说清旧版安装数据、外部 SAF 工作区和新应用各自归属；迁移不依赖删除 beta.5。
- 既有文件未损坏，Git 状态变化只来自本阶段新增文档／脚本。
- 任何尚未证实的版本、哈希和测试都标为待核实。
