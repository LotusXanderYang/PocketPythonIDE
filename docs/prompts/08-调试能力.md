# 阶段 8 提示词：后期调试能力

请执行本阶段，并遵守 `docs/prompts/00-共同约束.md`。只有 IDE 工作区、语言包运行与任务取消已稳定时才开始。首先做可行性验证，再决定投入完整 UI。不得把“运行并打印日志”命名为“调试”。

## 目标架构

IDE 实现通用调试界面和 DAP 客户端；语言包声明是否带 DAP 适配器。断点、继续、暂停、单步、调用栈、作用域、变量与异常停止按能力逐项开放。初版同一时间只需一个调试会话，设计上须可取消并清理子进程。

## 验证与实现次序

1. **Python**：在独立 Python 基础包中比较现有可移植调试适配器与必要的最小自研实现。以 Android ARM64 真机验证断点命中、单步、局部变量、多文件模块路径映射、异常停止和任务退出。若适配器依赖未移植的本地扩展，先解决依赖或缩小功能范围。
2. **C/C++**：单独研究 Android 上 LLDB 或其他可行调试器的打包、进程权限、符号文件和真实用户应用运行方式。制作最小两文件程序调试原型。若系统限制使普通用户设备上无法可靠调试，保留编译诊断能力，并发布阻断证据，不以需要 root 的路径冒充普遍支持。
3. **UI**：在确有可运行适配器后加入断点列、调用栈、变量窗格、调试工具条和状态提示。编辑器断点位置在文件修改、重命名和项目同步后仍应正确映射。
4. **协议**：记录 DAP 初始化、会话启动、断开、路径映射、能力声明和错误处理；语言包协议不支持时 UI 明确显示“此语言包不支持调试”。

## 交付物与验收

- Android 设备上的调试可行性报告、风险与支持矩阵。
- 已证明可行的语言适配器、IDE 调试 UI 和实机演示脚本。
- Python 至少通过断点、单步、变量、多文件和异常测试；C/C++ 只有通过同类实机测试后才宣称支持。
