# 双产品重构提示词

本目录把已批准的路线拆成可逐项交给 AI 编程助手执行的任务。目标是两个独立的开源 Android 应用：轻量通用 IDE，以及面向小模型训练的 Python · PyTorch Lab。发行渠道仅为 GitHub 源码仓库和 Releases；不规划 Google Play。

## 使用顺序

| 顺序 | 文件 | 完成后应看到什么 |
| --- | --- | --- |
| 先读 | [00-共同约束.md](00-共同约束.md) | 所有任务共享的产品边界和工程规则 |
| 1 | [01-固定基线与迁移.md](01-固定基线与迁移.md) | 可恢复的 beta.5 基线、回归清单、用户数据迁移设计 |
| 2 | [02-双应用工程拆分.md](02-双应用工程拆分.md) | 两个可并存安装的应用和共享源码模块 |
| 3 | [03-语言包接口与SDK.md](03-语言包接口与SDK.md) | Language Pack API v1、SDK、示例包和验证器 |
| 4 | [04-通用IDE界面.md](04-通用IDE界面.md) | 新界面、主题和工作区背景，同时保留编辑核心功能 |
| 5 | [05-C与CPP语言包.md](05-C与CPP语言包.md) | Android ARM64 实机多文件编译与运行原型 |
| 6 | [06-Python基础语言包.md](06-Python基础语言包.md) | 不含 PyTorch 的 Python 基础开发能力 |
| 7 | [07-PyTorch-Lab.md](07-PyTorch-Lab.md) | 独立的 CPU 小模型训练应用 |
| 8 | [08-调试能力.md](08-调试能力.md) | DAP 主机、Python 原型及 C/C++ 可行性结论 |
| 9 | [09-开源发布与验收.md](09-开源发布与验收.md) | 文档、许可证、签名和 GitHub Release 发布流程 |
| 制包模板 | [10-第三方语言包制包模板.md](10-第三方语言包制包模板.md) | 供用户填写变量后交给 AI 制作其他语言包 |

每次只提交**一个阶段文件**给 AI 助手，例如：“请执行 `docs/prompts/03-语言包接口与SDK.md`，同时遵守 `docs/prompts/00-共同约束.md`。”前一阶段未通过验收时，先修复问题，不要把未完成能力留给后续提示词掩盖。阶段 5、6、7 在阶段 3 的接口稳定后可分别推进；阶段 8 放在运行能力稳定之后。

这些文件是**实施提示词和验收要求**，不是已经完成的功能，也不是允许跳过实机验证的证明。项目目录中已有未提交改动；执行第 1 阶段前，任何 AI 助手都必须先只读检查 Git 状态并保护现有文件。

第 10 份是面向第三方制包的泛用模板，须先填入具体语言、设备与能力需求。API v1、SDK、示例包和验证器已提供；模板的确切字段与静态检查命令见 [API v1 制包提示词](../language-pack-api/v1/AI-PROMPT.md)。静态检查不能替代目标 ARM64 实机验收，未指定语言时不会自动制作语言包。
