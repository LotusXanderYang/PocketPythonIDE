# 共同提示词：产品边界与执行规则

你正在维护 `PocketPythonIDE` 开源 Android 工程。请先阅读本文件、当前任务文件、根目录 `README.md`、`app/build.gradle`、`app/src/main/assets/runtime.json`、相关源码、`docs/` 中的构建记录，以及存在的 `AGENTS.md`。先只读检查 `git status` 和现有构建产物，再提出本阶段的简短执行步骤并实施。用户已批准双产品总体路线；不要借此自行发布新版本或删除旧版数据。

## 产品定位

1. **通用 Android IDE**：面向携带平板和外置键盘的学生，侧重工作区、多文件、编辑、提示、本地构建和运行。基础 APK 要轻量。语言能力按真实支持情况由语言包提供。
2. **Python · PyTorch Lab**：独立安装的 CPU 小模型训练应用。复用现有 Python/PyTorch 移植成果和必要的共享源码，但界面、数据目录、包名、发布物与通用 IDE 分离。
3. 两个产品仅通过 GitHub 仓库与 Releases 开源发行。可用 GitHub 上的静态语言包目录，不建设服务器，也不规划 Google Play 分发或 Play Feature Delivery。

## 不可越过的边界

- `v0.1.2-beta.5` 是可回退基线。不得覆盖、改写其 GitHub Release、标签、用户工作区或安装数据。新应用采用不同 applicationId；迁移必须由用户明确操作、可验证、可回退。
- 仓库当前可能同时存在已暂存、未暂存和未跟踪文件。不得执行 `git reset --hard`、`git clean`、盲目的 `git add -A`、覆盖式复制或重新生成会清空旧构建缓存的命令。先确认所有者已有工作，再针对本阶段文件修改。
- Android 的 SAF `content://` 文档 URI 不是普通本地路径。沿用已有工作区复制／写回与冲突检测思想，并将提供者拒绝写入明确反馈给用户。不得声称所有鸿蒙原生目录可写。
- 不将 PC 原生二进制改名、解压后宣称 Android 可运行。原生包必须有 Android ABI、API、依赖闭包、可复现构建与实机结果。
- 不宣称任意 `pip` 包、GPU PyTorch、完整 LSP 服务或 C/C++ 调试天然可用。界面只暴露经过验证的能力；缺失能力给出原因和下一步。
- 安装语言包时应清楚显示来源、版本、签名／哈希、权限和兼容信息。不能仅凭一个 JSON 文件就把未知原生代码当可信执行。
- 保护用户源码和数据集：不隐式上传，不无提示覆盖，不以训练输出覆盖已有检查点。许可证和第三方声明随发布物提供。

## 每阶段工作方法

1. 读现状并标记会碰到的文件、已知设备和待验证设备；列出本阶段可交付的最小闭环。
2. 实施时把 UI、工作区、语言服务、执行进程和运行时构建分层；避免继续把所有逻辑加进 `MainActivity.java`。
3. 每个能力至少核验实际输入、输出、失败和取消路径。宿主机测试不能代替 Android 实机测试；未做实机测试就明确标注。
4. 结束时报告：改动文件、构建产物及大小、通过的测试、未通过或未测试项目、数据迁移影响、下一阶段依赖。只有真实完成时才称“已支持”。
5. GitHub 发布与设备安装只在相应任务明确要求且具备条件时执行；不要在每个阶段自动发 Release。

## 共同产品约束

- 首要设备是 ARM64 平板，外置键盘优先；保留 Android API 26 起的现有兼容基线，若需提高最低版本，必须给出理由与设备影响。
- 运行可能耗时，界面须可继续阅读和编辑；取消、日志和异常需可见。避免长任务直接阻塞 Activity。
- 基础 IDE 目标为不包含 PyTorch 的小型 APK。先测量当前拆分结果，再确定可信的大小目标；不能通过隐藏运行时下载来虚称轻量。
- 内置图标必须为项目自己的设计。不要复制 VS Code、PyCharm 等产品的图标或整体像素布局。
