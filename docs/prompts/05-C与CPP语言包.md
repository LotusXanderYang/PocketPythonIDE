# 阶段 5 提示词：C/C++ Android ARM64 语言包

请执行本阶段，并遵守 `docs/prompts/00-共同约束.md` 和已发布的 Language Pack API v1。先做工具链可行性验证，再决定正式打包方式。目标是面向课程练习的本地编译与运行，不是桌面 C/C++ 开发环境的完整复制。

## 先验证，再集成

1. 研究并记录可再分发的 Android ARM64 Clang／LLVM 工具链、标准库、头文件、链接器及许可证。区分**在 Android 上运行编译器**与**编译面向 Android 的程序**这两个问题。不得把 PC 版可执行文件直接放入 APK。
2. 在目标 Android 版本和设备上做最小原型：`hello.c`、两个 `.c` 文件、`hello.cpp`、两个 `.cpp` 文件分别编译、链接、运行。记录执行文件所在位置与方式，确认符合当前 Android 的可执行文件限制。若普通本地可执行文件方案不可行，应给出可靠的进程内或其他可用方案；若仍不可行，本阶段以证据充分的阻断报告结束，不伪装成已支持。
3. 验证标准输入、标准输出、标准错误、编译错误源码位置、非零退出码、超时和用户取消。先支持单目标项目、常见 `-std` 选择与文件包含；构建配置需可读、可修改，不默默使用错误的系统头文件。

## 接入 IDE

- 按 API v1 提供真实的语法、补全、诊断、构建和运行能力；补全初版可只做关键字、标准库常用符号和当前项目符号，需明确范围。
- 从 IDE 的工作区运行副本接收项目文件，构建产物保存在语言包私有空间或受控任务目录；不得把 SAF URI 当本地路径直接传给编译器。
- 构建任务独立于 IDE UI 进程，支持取消、输出流和错误定位。错误消息要提示缺少头文件、架构不兼容、设备限制等具体原因。
- 清单写出 ABI、最低 Android 版本、工具链版本、支持标准、运行限制、APK 大小、来源与许可证。GitHub 发布物附完整复现步骤和 SHA-256。

## 交付物与验收

- `packs/cpp/` 或等效独立模块中的源码、构建脚本、许可证与 API v1 清单。
- 实机记录：C/C++ 单文件、多文件、编译失败、运行异常、取消与重启后继续使用。
- 从空 IDE 安装该包、编译并运行一个两文件课程项目的完整操作路径。
- 若工具链体积或设备限制超出学生场景，给出测量值和可选择的缩减方案，而不是隐藏下载体积。
