# 阶段 9 提示词：开源文档、发布与最终验收

请执行本阶段，并遵守 `docs/prompts/00-共同约束.md`。先核对各阶段真实完成状态。此提示词授权准备发布材料和进行本地验证；**只有用户另行明确要求发布时**，才创建 GitHub Release 或上传 APK。发行渠道仅为 GitHub，不添加 Google Play 相关流程。

## 整理与验证

1. 分别维护通用 IDE、Python · PyTorch Lab、语言包 API 与首批语言包的 README。首页说明产品定位、支持设备、安装方法、已实现／未实现能力、应用体积、数据迁移、常见失败以及从源码构建方式。
2. 为每个发布 APK 生成 SHA-256、版本号、包名、ABI、最低 Android 版本、签名信息与对应源码提交。检查依赖许可证及第三方声明，并确保二进制来源可追溯。
3. 建立 GitHub 静态语言包目录和 JSON Schema 验证流程。目录只列真实发布的语言包，标出工具链大小、能力、兼容条件、Release 下载地址和最后实测设备。
4. 在 ARM64 Android 平板完成从全新安装到打开工作区、创建多文件项目、安装语言包、构建／运行、卸载语言包的端到端测试。Lab 完成训练与检查点流程。鸿蒙兼容环境单独验证 SAF 可写目录，并记录不可写目录的清晰提示。
5. 测量 IDE 基础 APK、各语言包和 Lab 的下载大小与安装后存储；与 beta.5 对比，写清轻量化来自哪里。记录首次启动与常见任务耗时，不编造未测数据。
6. 整理发布说明、升级／迁移说明、已知问题和回滚方法。版本号体现测试版状态；未达到验收门槛的语言包只能标实验性，不放进“已支持”列表。

## 发布边界

- 不改写 `v0.1.2-beta.5` 标签与 Release，不删除其附件。
- 如果用户明确要求发布：先核对将发布的确切提交、APK 和哈希，再创建对应的新标签与 Release；上传完成后核验 GitHub 页面与附件哈希，并回报链接。
- 如果尚无发布授权：只交付本地 APK、哈希和可审阅的 Release 文案，等待用户指示。

## 验收

- 新用户仅依据 README 能复现 IDE 与 Lab 的安装、基本使用和源码构建；接口贡献者仅依据规范和示例能制作语言包。
- GitHub 文件、源码提交、版本号、哈希和实机测试记录一一对应。
- 旧版工作区可继续使用，迁移失败有明确回退路径。
