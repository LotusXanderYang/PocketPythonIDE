# 阶段 4 提示词：重做通用 IDE 界面

请执行本阶段，并遵守 `docs/prompts/00-共同约束.md`。依赖双应用拆分和语言包能力接口。目标用户主要在 Android 平板上使用外置键盘，界面以学习开发任务为中心；不要复制 VS Code 或 PyCharm 的图标和整体布局。

## 先做设计

1. 检查现有全部界面、快捷键、菜单和编辑规则，列出必须保留的功能：SAF 文件夹工作区、文件树、多标签、保存、输出、代码提示、Tab 缩进、括号／引号配对、冒号后缩进、字体大小、运行与错误提示。
2. 先提交两套低保真布局方案和一套最终设计稿说明，包括平板横屏、较窄窗口、实体键盘焦点顺序、空工作区、无语言包、构建失败及长任务运行状态。用户已授权选择合理方案，但若改变核心工作流程，要解释理由。
3. 建立设计 token：间距、边框、少量圆角、字体、对比度、深浅配色、可选主体色和自己的图标语言。图标可识别且有文字提示，不复刻其他 IDE 图形。

## 实施范围

- 顶部：工作区与文件切换、搜索、构建／运行、当前语言环境、设置；低频动作放入菜单。
- 左侧：可折叠文件树、项目搜索、语言包与任务入口。中央保留编辑器和标签；底部整合输出、问题与构建记录。宽度与面板可调整并保存。
- 主题：浅色、深色和若干可选主体色；系统字体缩放与当前字体设置继续有效。
- 背景：由用户通过 SAF 选择图片；仅在编辑工作区背层显示，提供模糊、雾化、降饱和度、不透明度与一键重置。处理大图时采样缩放并在后台生成缓存，避免内存峰值和输入卡顿；文字前增加遮罩并维持可读对比度。低性能设备可关闭效果，URI 失效时回到纯色。
- 实体键盘：保留现有快捷键，补充文件／标签切换、搜索、构建和面板焦点的可发现入口；补全弹窗的方向键、Enter、Esc 行为一致。触屏仍可完成基本操作，但不以触屏手势作为唯一入口。
- 语言包状态：区分“仅编辑”“可检查”“可运行”“可调试”；没有安装运行包时不显示误导性的运行成功提示。

## 交付物

- 设计说明与关键状态截图，包含所选布局理由和 token 表。
- 实现后的 IDE APK、主题与背景设置说明、键盘快捷键表。
- 编辑核心功能的回归记录，以及至少一台平板横屏的操作记录。

## 验收

- 打开工作区、创建／保存多文件、补全、键盘缩进和构建输出不因 UI 重构退化。
- 背景高强度设置仍可读；关闭效果后无残留缓存或明显性能损失。
- 活动任务和错误状态可见，未安装语言包时操作给出正确引导。
