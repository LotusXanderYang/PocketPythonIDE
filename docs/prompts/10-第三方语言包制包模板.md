# 第三方语言包 AI 制包提示词模板

本模板的具体字段与命令已落实到 [API v1 制包提示词](../language-pack-api/v1/AI-PROMPT.md)。请优先使用该文件、[接口规范](../language-pack-api/v1/README.md)及[可选调试通道](../language-pack-api/v1/DEBUG.md)；阶段 3 的设备验收状态见 [历史验证记录](../language-pack-api/v1/VALIDATION.md)。当前 IDE 发布版本为 `0.2.0-alpha.2`，包清单的 `minHostVersion` 仍固定为 `0.2.0-alpha.1`，这是 API v1 兼容基线。此文是供具体语言填充的模板，不代表已选定语言或已完成任何第三方包。

---

请为开源 Android 通用 IDE 制作 `<语言名称>` 语言包。目标是 `<课程或项目场景>`，上游工具链／解释器版本为 `<版本及官方源码地址>`，目标设备为 `<设备型号>`、Android `<版本>`、ABI `<arm64-v8a 等>`，最低支持版本为 `<最低 Android API>`。我需要的能力是 `<语法着色／补全／诊断／构建／运行／调试，逐项列出>`。项目仓库为 `<GitHub 仓库地址>`，正式规范位于 `docs/language-pack-api/v1/`，SDK 与示例包路径为 `<实际路径>`。

## 开工前

1. 阅读 API v1 全文、SDK、示例包、验证器与仓库的 `AGENTS.md`；只读检查 Git 状态。不要覆盖既有未提交工作。先把需求拆成“已证实可行、需原型验证、当前不可行”三类。
2. 使用该语言的官方源码、官方构建说明和 Android 官方文档核实 ABI、最低 API、C/C++ 运行库、动态库、子进程、文件访问与许可证。核对二进制依赖闭包；不要把 Linux/glibc 或 Windows/macOS 二进制改名当作 Android 产物。
3. 先在设备上做最小运行原型。若编译器或解释器无法在普通用户设备上可靠运行，停止宣称运行能力，保留可用的纯编辑能力，并提供阻断证据与替代方案。当前 IDE 同一时刻只启用一个可执行语言包；测试切换包时应重新验证和启用。

## 实现要求

1. 建立独立 Android 语言包 APK，按 API v1 提供服务；使用正式 Schema 编写包内清单。只声明实测通过的能力；未实现项写为不可用并说明原因。APK 构建与签名后先准备候选索引条目；只有实际上传 GitHub Release 并核验附件后，才把 SHA-256、签名证书指纹、Release 地址、文件大小和兼容范围写入公开静态索引。
2. 通过 IDE 授予的受控项目副本或文件描述符读取任务输入。支持任务 ID、取消、超时、输出流、诊断位置和非零退出码；不得把 SAF `content://` URI 当作本地文件路径，不得隐式上传用户源码。
3. 至少验证单文件项目、多文件项目、语法或编译错误、运行错误、取消、包更新与卸载。若能力不适用，明确写出理由。调试功能只有在真实断点、单步、变量、调用栈、停止和再次调试通过后才能声明；须按独立调试通道规范实现 `debugAdapter` 和 `selfTests.debug`。
4. 输出源码、可复现构建脚本、依赖版本与许可证、包内清单、拟加入 GitHub 静态索引的条目、APK、SHA-256、签名证书指纹、最小示例项目、验证器运行结果和 ARM64 实机记录。静态验证命令为 `python tools/verify-language-pack.py --apk <目标APK> --manifest <包清单源码JSON>`；它只检查 Schema、清单及 APK 结构，不能替代 IDE 内的自检和端到端操作。未正式发布前不要把包加入公开静态索引。构建日志与测试记录必须能对应确切源码提交和 APK 哈希。
5. 写给学生的安装与使用说明：需要多少下载／安装空间、支持哪些文件、怎样构建与运行、常见错误含义、当前不支持什么。不得声称兼容任意 PC 包或所有第三方库。

## 完成判定

只有正式 API v1 验证器通过，并且至少一台目标 ARM64 设备完成对应能力的端到端测试，才将语言包标为“已支持”。如果缺少设备或工具链，就交付可审阅的源码、未通过项、下一步验证命令和明确的实验性标签，不伪造结果，也不替我发布 GitHub Release。
