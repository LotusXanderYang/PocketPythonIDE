# 阶段 2 提示词：拆成通用 IDE 与 PyTorch Lab 两个应用

请执行本阶段，并遵守 `docs/prompts/00-共同约束.md`。先阅读阶段 1 的基线与迁移文档。此阶段以可构建、可并存、可回退为目标；不要顺带重做 UI 或尝试压缩 PyTorch 算子。

## 任务

1. 将现有单 `:app` 结构整理为可维护的 Gradle 多模块工程：两个 Android 应用模块，以及仅在确有复用时建立的编辑器、SAF 工作区、任务／日志等共享库模块。不要为了模块数量而抽象。
2. 确定两个新的稳定 `applicationId`、应用名和版本线，写入架构文档。旧 `com.example.pocketpythonide` beta.5 保持可安装；新包名须同时安装且不读取旧版私有目录。
3. 通用 IDE 不打包 `runtime.zip`、PyTorch `.so`、Torch 专属 UI 或训练依赖。Lab 保留现有 CPython、NumPy、PyTorch 运行时与来源清单，并使启动、导入和自检继续有效。
4. 将现有 `MainActivity.java` 中可复用的编辑器与工作区逻辑逐步抽出，保持创建、打开、保存、错误提示和键盘操作行为。运行任务不应阻塞 UI 线程；原生运行时故障隔离需求至少形成明确设计和原型。
5. 实现用户可选择的迁移入口或先提供可实际完成的导出／导入流程。严禁无提示读取或改写旧版数据。
6. 更新本地构建脚本，使单独构建某个应用无需重建全部 PyTorch 运行时；保留可复现的完整构建入口。

## 交付物

- 两个可安装的调试 APK；明确记录包名、版本、文件大小和 SHA-256。
- 模块图、依赖方向、运行时归属与数据边界文档。
- 实际可用的独立构建命令及最小验证脚本。

## 验收

- 同一 ARM64 设备上，新 IDE、新 Lab 与旧 beta.5 能并存启动。
- IDE APK 内不含 Python/PyTorch 运行时；Lab 完成现有运行时自检，未能实测时明确保留为未完成门槛。
- SAF 工作区中的用户文件未丢失；新旧应用之间没有静默覆盖。
